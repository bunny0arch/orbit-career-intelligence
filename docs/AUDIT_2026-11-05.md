## Architecture verified in source

The application is a React + TypeScript + Vite frontend served locally through an Express/Vite middleware server. Domain records are typed in `src/lib/types.ts`; seeded role, skill, roadmap, certification, and achievement data lives in `src/data/seed.ts`; deterministic readiness calculations live in `src/lib/scoring.ts`; browser-local persistence and the local session boundary live in `src/lib/storage.ts`; server-side AI routing lives in `server/ai.ts`.

The UI is a single routed shell in `src/app/App.tsx`, with accessible Radix-based Tabs and Progress wrappers, a copied/adapted AnimatedList, Lucide icons, and Orbit-specific compositions. `public/manus-routes.json` declares the nine page routes. The project intentionally uses local demo-safe state instead of Supabase persistence.

## Concrete unfinished or partial features

### P0 / production-critical

1. **Authentication is a local prototype, not authentication.** `AuthScreen` accepts any valid-looking username/password and does not create or verify credentials, enforce uniqueness, restore a secure server session, rate-limit attempts, or provide recovery. `storage.ts` stores only a local session username. This must be replaced by server-side username mapping to Supabase Auth, secure cookies, anti-enumeration behavior, transactional uniqueness, and RLS owner checks.
2. **Persistence is browser-local.** Profile, skills, roadmap, certification, achievement, and assessment changes are stored in `localStorage`; there are no migrations, repositories, sync, conflict handling, or cross-device continuity. The backend schema and authenticated API are still required.
3. **Evidence is modeled but not submitted or reviewed.** Skills show provenance labels, but there is no project/evidence attachment flow, assessment rubric, evidence history, reviewer workflow, private storage, or signed URL boundary.
4. **Certification proof is a state transition only.** `addProof` changes a label to `pending review` without a file picker, private storage upload, metadata, or reviewer decision.
5. **RAG and source validation are not implemented.** Role source labels are seeded metadata; there is no approved-document ingestion, passage retrieval, citation validation, freshness handling, or opportunity ingestion.
6. **AI output is unstructured text.** Career Brain is explanatory only, which is safe for the prototype, but production recommendations need schema validation, citations/uncertainty fields, provider telemetry, and authenticated profile context from the backend.

### P1 / product-completeness gaps

- Skill assessment and weak-topic storage are not implemented; the dashboard's assessment date is a local string.
- Career Time Machine/hypothetical non-mutating scenario comparison is not implemented.
- Project records, public repository analysis, confirmation of extracted skills, and evidence snippets are not implemented.
- Adaptive roadmap generation is currently a deterministic appended task, not a provider-backed or rubric-aware ordered plan with prerequisites and validation criteria.
- Achievement unlocking covers the seeded roadmap-completion path but lacks a general deterministic rule engine and duplicate safeguards for all criteria.
- Opportunity Radar, verified opportunity records, notifications, reviewer/admin console, audit logs, advanced assessments, and Android client remain deferred.

## Defect fixed in this continuation

The baseline only exposed `/api/health` and `/api/ai/career-brief` through the local Express runtime. A Vercel Vite deployment would serve the frontend bundle but would not have those API routes. This continuation:

- added `api/health.ts` and `api/ai/career-brief.ts` as Vercel serverless handlers;
- added shared bounded payload validation in `server/request.ts` and applied it to both local and Vercel runtimes;
- made provider failures return a stable generic 502 response rather than leaking provider error text;
- added `vercel.json` with explicit Vite build/output settings; and
- documented the server-side environment-variable boundary in `README.md`.
